# モデルの研究室(チャンピオンとチャレンジャー)

目的: 期待スコアのモデルを、決算短信なども含めて**総合的に判断する方向へ少しずつ進化させる**。
毎週の研究タスク(`research/improve_prompt.md`、毎週土曜 9:00)が、案を試して記録し、良い案は本番と並走させ、
条件をすべて満たしたら利用者に「本番に入れてよいか」を聞く。

## 3つの段階
| 段階 | 何をするか | 置き場所 |
|---|---|---|
| 1. 検証(過去) | どの案も同じ方法(`lab.py`)で採点して一覧に並べる | `leaderboard.csv` |
| 2. 並走(これから) | 良い案をチャレンジャーとして毎日採点し、選んだ銘柄を記録。サイトの表示は変えない | `jpstocks/challenger.py`、`models/challengers/`、`reports/shadow_picks.csv` |
| 3. 昇格 | 条件をすべて満たしたら、研究タスクが報告して**利用者の承認を待つ**。承認されたら本番を切り替える | 報告書と会話 |

## 本番に入れる条件(昇格ゲート)
1. **ゲート1(過去の検証)**: `lab.py` で、3か月の最終候補の成績が REF(今の特徴量・乱数10通りの平均)より良く、
   差の t が `required_t`(試した案が5個以下 2.0 / 20個以下 2.5 / それ以上 3.0)以上、8年中6年以上で上回る
2. **ゲート2(並走)**: 本番と並走して、3か月たった日が60営業日以上あり、その平均でチャンピオン以上(`scripts/25_shadow_eval.py` → `shadow.md`)
3. 両方を満たしたら、報告の先頭に「昇格候補あり」と書いて利用者に聞く。**自動では切り替えない**

ゲート1を満たさない案でも、ゲート1の差が +0.3% 以上・8年中5年以上なら、並走させてよい(並走は本番に影響しないので、
将来のデータでの答え合わせを早く始める)。並走は同時に3つまで。

## 今のチャンピオンとチャレンジャー
| 役割 | 名前 | 中身 | 過去の検証(3か月の最終候補) | 並走の開始 |
|---|---|---|---|---|
| チャンピオン | 本番 | 今の特徴量33個、勾配ブースティング1つ(乱数0) | +1.6%(REF +2.3%) | − |
| チャレンジャー | M1_ens5 | 今の特徴量 + 決算短信の8個、乱数5通りの平均 | +2.7%(REF との差 +0.5%、t 0.5、8年中5年) | 2026-11-09 |

M1_ens5 はゲート1を満たしていないが、「決算短信も加味して総合的に判断したい」という利用者の希望(2026-11-07)を受けて、最初のチャレンジャーとして並走させる。

## 使い方
- 一覧: `python research/lab/lab.py`
- 案を試す: `research/experiments/YYYY-MM-DD_テーマ.py` の中で `import lab` して `lab.predict(...)` → `lab.record(...)`
- 新しい特徴量: その日までに分かる情報だけで作り、`lab.add_features(df, "名前")`(列: code, date, 特徴量…)
- チャレンジャーにする: `jpstocks/challenger.py` の `SPECS` に足し(新しい種類の特徴量なら、本番のデータで作る関数も足す)、
  `python scripts/26_train_challenger.py 名前` → `python scripts/21_daily_report.py --no-update --no-open` で動くことを確かめて
  `models/challengers/名前.pkl` を commit。やめるときは pkl を消す(記録は shadow_picks.csv に残る)
- チャレンジャーの学習し直し: 月1回(月の最初の土曜)。`python scripts/26_train_challenger.py`
- 並走の答え合わせ: `python scripts/25_shadow_eval.py`

## 注意
- 検証のデータ(`data/wf_jq_3m.parquet`)は上場廃止を含む J-Quants の株価(配当なし)。並走は本番と同じ yfinance の株価
- 案をたくさん試すほど、偶然良く見える案が混ざる。だから過去の検証だけでは本番に入れず、並走(将来のデータ)で確かめる
- J-Quants のデータそのものは公開しない(`data/` は commit しない。モデルの pkl には木の分かれ目の値しか入らない)
